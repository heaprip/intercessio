# Спайк: свод правил репозитория как корпус

**Не принято.** Проверка идеи, а не часть конструкции.

Тот же движок и та же семантика (`spike/legal-engine/core.pl`), другой корпус:
вместо норм политии — правила работы в репозитории, извлечённые из `AGENTS.md`
и `docs/README.md`.

Прогон: `spike/agent-rules/run.sh` (после `scripts/setup-spike.sh`).

## Что здесь

- `contract.pl` — правила про **действия**, у каждого объявлен источник.
  Прозаические требования сюда не идут: непроверяемое правило в корпусе — это
  провал `duty-without-consequence`, обязанность без последствия;
- `session.pl` — что делалось в этой сессии, плюс контрольные случаи, которых
  не было;
- `extract.sh` → `repo.pl` — факты, вытащенные из репозитория: статусы решений,
  утверждение главы 6. Ничего не интерпретирует;
- `corpus.pl` — проверки согласованности самого корпуса;
- `run.sh` — прогон с записанными ожиданиями.

## Два разных вопроса, один движок

1. **Допустимо ли действие** — перед записью;
2. **Не противоречит ли написанное написанному** — то же, что линтер делает с
   конституцией игрока.

## Что нашлось

**Пробел в самом контракте.** `AGENTS.md` говорит и «прямое поручение автора
снимает умолчание», и «перенос материала в остальные каталоги делает автор».
Какое сильнее — не сказано. Поэтому на вопрос «можно ли по поручению писать
прямо в `docs/decisions/`» движок молчит в обе стороны: ни разрешено, ни
запрещено. Это не дефект движка, а ровно тот исход, ради которого он нужен:
пробел предъявлен, а не закрыт догадкой.

Порядок между этими двумя правилами намеренно **не объявлен** — объявить его
может только автор.
