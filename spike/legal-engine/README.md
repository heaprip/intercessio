# Спайк: влезает ли юридический слой в готовый движок

**Не принято.** Каталог одноразовый: он проверяет гипотезу, а не является
частью конструкции. Ничего отсюда не является основанием для решения, пока
автор не перенесёт вывод в `docs/`.

Ставится: `scripts/setup-spike.sh`. Прогон: `spike/legal-engine/run.sh`.

## Что здесь

- `core.pl` — семантика опровержимых правил. Пишется один раз и является тем,
  что в проекте называется вычислителем: сила правил, вытеснение, defeater,
  три исхода;
- `cases/` — по файлу на вопрос, который спайк должен был решить;
- `run.sh` — прогоняет каждый случай и сверяет с ожидаемым исходом. Ожидание
  записано в скрипте, поэтому регрессия видна, а не вспоминается.

## Что установлено

| Случай | Ожидание | Что проверяет |
| --- | --- | --- |
| `chain-replicatio` | вывод есть | цепочка intentio - exceptio - replicatio |
| `chain-exceptio` | вывод есть | исключение бьёт общее правило |
| `unordered-conflict` | моделей нет | non liquet при необъявленном порядке |
| `vested-protection` | моделей нет | A4 как defeater держит приобретённое |
| `competence` | вывод есть | назначение вытесняет умолчание «не компетентна» |
| `dropped-exception` | вывод есть | правило-исключение молча выпадает |
| `dropped-exception --unknown=error` | ошибка | и ловится флагом движка |

## Поправка, которую спайк нашёл

Первая версия семантики считала правило вытесненным, если **существует более
сильное противоположное**. При необъявленном порядке это выдаёт **оба** вывода
сразу, то есть противоречие вместо `non liquet`.

Правильное условие: правило вытеснено, если существует **применимое
противоположное, которое оно не бьёт**. Разница в одном слове, поведение
противоположное. Ошибка найдена прогоном, а не чтением.
