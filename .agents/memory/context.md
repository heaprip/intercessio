# Контекст проекта для быстрого входа

Intercessio — Go-монолит для римско-вдохновленной симуляции институционального
рассмотрения запросов людей. Люди и часть институциональных actors могут
генерироваться LLM разной мощности. Конституция, кодексы и другие нормативные
документы задают права, обязанности, компетенцию и порядок принятия,
оспаривания, veto и исполнения решений.

Базовые намерения автора:

- модульный монолит, DDD и гексагональная архитектура;
- event-driven поведение без зависимости доменных фактов от broker;
- нативные Go-тесты, симулирующие людей, институты и время без инфраструктуры;
- институциональное разделение полномочий и запрет самоприсвоения competence;
- LLM предлагает или играет ограниченную роль, но не создает себе authority;
- римская стилистика является частью предметной рамки и UI, но не обещанием
  исторической реконструкции;
- критическая, а не подтверждающая роль AI-помощника.

Принятые технические направления:

- переносимость определяется наблюдаемыми гарантиями durable commit;
- каноническим workflow state владеет Intercessio, managed engine может быть
  runner;
- внешний API proto-first: REST/JSON через gRPC-Gateway и возможность native
  gRPC;
- внутренние модули не общаются через loopback HTTP/gRPC.

YDB остается основным исследуемым serverless-вариантом, AWS — возможным путем
отступления. Provider, границы event sourcing и custom OpenFGA datastore не
приняты окончательно. Точный состав институтов и bounded contexts также является
гипотезой.
