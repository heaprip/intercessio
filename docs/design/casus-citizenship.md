# Казус: получение гражданства

Первый вертикальный срез — прошение о статусе. Разбор служит одной цели:
вывести схему предикатов из конкретики, а не из рассуждения, и проверить, хватает
ли выбранного представления.

Запись условная — это способ увидеть форму правил, а не синтаксис реализации.
Идентификаторы английские по конвенции репозитория.

## Минимальный мир

Три должности: две независимые компетенции плюс путь блокировки.

| Должность | Ответственность | Срок |
| --- | --- | --- |
| `praetor` | принимает прошение, формулирует подлежащий проверке вопрос, выносит решение | 1 период |
| `censor` | устанавливает факты о людях | 2 периода |
| `tribunus` | intercessio на решение до вступления в силу | 1 период |

Два статуса и их пучки прав:

- `peregrinus` — `ius_commercii`;
- `civis` — `ius_commercii`, `ius_conubii`, `ius_suffragii`, `ius_honorum`.

Люди: `marcus` — перегрин, служит во вспомогательных частях с периода 5.

## Нормативный корпус

**Уровень 1, конституция:**

- `A1` — перечень статусов и состав пучков прав;
- `A2` — компетенции должностей и сроки;
- `A3` — процедура изменения норм;
- `A4` — закон не имеет обратной силы, приобретённое защищено.

**Уровень 2, кодекс о гражданстве:**

- `C1` — перегрин с выслугой не менее 25 периодов и подтверждённой выслугой
  имеет право на гражданство; норма конститутивная;
- `C2` — исключение: не имеет, если есть вступившее в силу решение о проступке;
- `C3` — возражение на исключение: имеет, если проступок погашен заслугой.

`C1`–`C3` воспроизводят римскую цепочку `intentio` → `exceptio` → `replicatio`.

## Факты

Хранимое, с провенансом:

```
served(marcus, 5, open).
established(f1, tenure_confirmed(marcus), censor, 30).
petition(p1, marcus, citizenship, 30).
occupies(gaius, praetor, 31, 31).
decision(d1, p1, grant, praetor, 31).
in_force(d1, 32).
```

`open` — незакрытый интервал: конец подставляется текущим периодом при чтении
среза, см. [[docs/design/corpus-and-facts|corpus-and-facts]]. Переписывать факт
каждый период нельзя, факты неизменны.

## Правила вывода

`⇒` — опровержимое правило, `⇝` — defeater: ничего не выводит, только блокирует
чужой вывод. `¬` в голове означает вывод об отсутствии.

```
% выслуга — вычитание над номерами периодов
r_tenure   served(P, From, To)                        ⇒  tenure(P, To - From)

% C1 — intentio: общее правило
r_c1       status(P, peregrinus), tenure(P, N), N >= 25,
           established(_, tenure_confirmed(P), _, _)  ⇒  entitled(P, civis)

% C2 — exceptio: исключение
r_c2       offense(P, O)                              ⇒ ¬entitled(P, civis)

% C3 — replicatio: возражение на исключение
r_c3       offense(P, O), merit(P, M), covers(M, O)   ⇒  entitled(P, civis)

% статус: C1 конститутивна, держится на факте решения, не на основании
r_status   decision(D, Pt, grant, _, _),
           petition(Pt, P, citizenship, _), in_force(D, _)  ⇒ status(P, civis)
% наследуемость объявлена у статуса, а не зашита в правило: civis передаётся
% по рождению, состояние вольноотпущенника — нет
r_born     born_to(P, Q), status(Q, S), heritable(S)  ⇒  status(P, S)
r_edict    edict(E, all_free), free(P), in_force(E, _) ⇒ status(P, civis)

% лишение
r_revoke   revocation(R, P, S), in_force(R, _)        ⇒ ¬status(P, S)
r_strip    strips_vested(N, S), applies_to(N, P)      ⇒ ¬status(P, S)

% A4 — защита приобретённого: норма корпуса, выраженная defeater
d_a4       norm_in_force(a4)                          ⇝  status(P, S)

% компетенция: закрытость мира — правило по умолчанию
r_nocomp                                              ⇒ ¬competent(Off, Kind)
r_comp     responsibility(Off, Kind)                  ⇒  competent(Off, Kind)
r_ultra    performed(Act, _, Off, Kind),
           ¬competent(Off, Kind)                      ⇒  ultra_vires(Act)

% права и связь права с делом
r_rights   status(P, S), bundle(S, R)                 ⇒  holds_right(P, R)
r_grant    competent(Off, grant_status),
           entitled(P, S)                             ⇒  may_grant(Off, P, S)
```

`r_grant` — то, ради чего существует `entitled`. Без него право на гражданство
никуда не подключено: претор мог бы выносить решение, не сверяясь с основанием,
и `C1` не влияла бы ни на что.

## Отношение вытеснения

```
r_c3  >  r_c2  >  r_c1
r_revoke  >  d_a4  >  r_strip
r_comp  >  r_nocomp
```

| Выше | Ниже | Основание порядка |
| --- | --- | --- |
| `r_c3` | `r_c2` | цепочка возражений **внутри одного документа** |
| `r_c2` | `r_c1` | там же |
| `r_revoke` | `d_a4` | конституция допускает лишение по явному основанию |
| `d_a4` | `r_strip` | `A4`: приобретённое не отнимается задним числом |
| `r_comp` | `r_nocomp` | назначение бьёт умолчание «не компетентен» |

**Порядок объявлен, а не выведен из уровней документов, и это видно здесь.**
`C1`, `C2` и `C3` лежат в одном кодексе, и порядок между ними задан напрямую:
иерархия документов о нём ничего не знает. А `A4` — норма конституции, то есть
высшего уровня, — стоит **ниже** `r_revoke`. Иерархия документов является одним
из источников этого отношения, а не самим отношением.

Незаполненная пара — не ошибка. Если два правила выводят противоположное и
порядок между ними не объявлен, не выводится ничего: дело получает исход
[[docs/concepts/non-liquet|non liquet]].

## Схема предикатов

- **о людях:** `status/2`, `served/3`, `born_to/2`, `free/1`;
- **о фактах:** `established/4` — что, кем, в каком периоде;
- **о делах:** `petition/4`, `decision/5`, `in_force/2`, `performed/4`;
- **о должностях:** `occupies/4`, `responsibility/2`;
- **о нормах:** `bundle/2`, `duty_bundle/2`, `heritable/1`, `edict/2`,
  `norm_in_force/1`, `strips_vested/2`, `applies_to/2`;
- **об обязанностях:** `duty/5` — носитель, адресат, что, вид, срок; `bears/3`
  — свидетельство исполнения; `exempt/3`, `about/3`, `resolved/1`;
- **о проступках и заслугах:** `merit/2`, `covers/2`, `revocation/3`;
  `offense/2` **выводится** из вступившего в силу решения, а не вносится;
- **выводимое:** `tenure/2`, `entitled/2`, `competent/2`, `ultra_vires/1`,
  `holds_right/2`, `may_grant/3`, `duty/5`, `borne/3`, `violated/3`,
  `offense/2` и отрицательные выводы по `entitled`, `status`, `competent`,
  `duty` и `borne`.

Это тот фиксированный набор, под который пишется
[[docs/design/deduction|вычислитель]].

## Сценарий

1. **Период 30.** Марк достиг выслуги 25. Ценз установил факт. Марк подал `p1`.
2. **Период 31.** Претор проверил `may_grant` и вынес `d1` о предоставлении.
   Трибун не возразил.
3. **Период 32.** Решение вступило в силу. Марк — `civis`, пучок прав выведен.
4. **Период 35.** Auctor правит `C1`: требуется 30 периодов, норма объявлена
   действующей **с периода 28**.

   Марк статус **не теряет**: `C1` конститутивна, `A4` в силе. Но линтер
   фиксирует ретроактивность: правка объявлена с периода 28, задето столько-то
   незавершённых дел, вступившие в силу решения защищены `A4`.
5. **Период 40.** Auctor отменяет `A4` либо принимает норму, прямо лишающую
   приобретённого. Отрицание в `vested_protected` переворачивается, пересчёт
   снимает статус у Марка и у всех, кто получил его на том же основании.

   Отчёт называет точное число и поимённо. Это уже не ошибка, а сознательное
   действие, и линтер помечает его как отнятие приобретённого.

Двухшаговость здесь существенна: отнять у людей полученное можно, но только
явным актом, который датирован, виден и предъявляем. Этого не даёт ни жёсткая
заморозка в движке, ни безусловный пересчёт.

## Обязанность: повинность и освобождение

Первая часть казуса брала проступок входным фактом. Здесь он выводится, и
заодно проверяются оба вида обязанности.

К минимальному миру добавляется одна норма кодекса: **гражданин несёт
повинность**. И одна конституционная возможность: освобождение по основанию.

```
% повинность — обязанность-состояние: лежит, пока человек гражданин
r_munus    status(P, civis)                     ⇒  duty(P, munus, maintain, _)

% освобождение — разрешение: ничего не выводит, только снимает
d_exempt   exempt(E, P, munus), in_force(E, _)  ⇝ ¬duty(P, munus, maintain, _)

% исполнение: по умолчанию не исполнено, свидетельство вытесняет умолчание
r_unborne                                       ⇒ ¬borne(P, K, N)
r_borne    bears(P, K, N)                       ⇒  borne(P, K, N)

% нарушение состояния — в любом периоде, когда обязанность лежит и не исполнена
r_viol_m   duty(P, K, maintain, _),
           ¬borne(P, K, N)                      ⇒  violated(P, K, N)

% нарушение достижения — по истечении срока
r_viol_a   duty(O, A, achieve, D), N > D,
           ¬borne(O, A, _)                      ⇒  violated(O, A, N)

% претор обязан разрешить дело до предельного срока — обязанность-достижение
r_decide   petition(Pt, _, _, N0), ¬resolved(Pt) ⇒ duty(praetor, decide(Pt),
                                                        achieve, N0 + limit)

% последствие нарушения — вторичная обязанность
r_repair   violated(P, munus, N)                ⇒  duty(P, penalty(munus),
                                                        achieve, N + 1)

% проступок появляется только из вступившего в силу решения
r_offense  decision(D, C, guilty, _, _),
           about(C, P, K), in_force(D, _)       ⇒  offense(P, K)
```

Порядок вытеснения дополняется двумя парами:

```
r_borne  >  r_unborne          свидетельство исполнения бьёт умолчание
d_exempt >  r_munus            освобождение снимает повинность
```

### Сценарий продолжается

**33.** Марк — гражданин с периода 32, значит `r_munus` даёт ему повинность.
Освобождения у него нет.

**34.** Повинность не исполнена. `r_viol_m` выводит нарушение. Это **повод**, а
не проступок: движок утверждает лишь, что долг не исполнен.

**35.** Нарушение порождает дело. Претор рассматривает, трибун не возражает,
решение вступает в силу — и только теперь `r_offense` даёт `offense(marcus,
munus)`.

С этого момента у Марка есть проступок, и в первой части казуса срабатывает
`r_c2`: прошения о гражданстве от людей в таком положении блокируются, пока
проступок не погашен заслугой.

Круг замкнулся. То, что в первой части было входным фактом, теперь выводится
полной цепочкой, и ни одно звено не пропущено.

### Что показал этот фрагмент

- **разрешение оказалось тем же defeater**, что и защита приобретённого. Ни
  одного нового механизма: `d_exempt` ничего не выводит, он не даёт вывести
  обязанность. Отмена освобождения возвращает повинность сама;
- **закрытость мира выражается умолчанием.** «Не исполнено, пока не доказано
  обратное» — правило с пустым телом, вытесняемое свидетельством. Тот же приём,
  что и с компетенцией;
- **два вида обязанности требуют разного отслеживания.** Состояние проверяется
  каждый период, достижение — на границе срока. Это единственное место, где
  цена решения ощутима;
- **нарушение и проступок разведены жёстко.** Иначе вывод движка становился бы
  приговором, а обвинение хранилось бы как совершённое преступление.

## Что вскрылось

### Арифметика подтвердилась и обошлась дешевле ожидаемого

`r_tenure` — арифметика, которой в чистом выводе по правилам нет. Минимально
необходимое расширение: **сравнение и вычитание над номерами периодов**, и
ничего больше.

Агрегации удалось избежать: служба хранится интервалом, а не фактом на каждый
период, поэтому считать нечего. Правило моделирования стоит того, чтобы быть
записанным явно, — иначе агрегация протащится в вычислитель и потянет за собой
собственный порядок вычисления.

### Вид нормы решает вопрос об основании

Первоначально статус выводился из основания, и ретроактивная правка снимала его
автоматически. Это было ошибочным распространением правила «незавершённое дело
идёт по действующему корпусу» на **вступившие в силу** решения.

В праве господствует противоположная модель — `tempus regit actum`, акт
оценивается по закону момента его совершения. Гражданство защищено сильнее
прочего: лишение почти везде допустимо только при обмане при получении, то есть
когда ложными были факты, а не когда изменились правила.

Разрешено видом нормы: конститутивная порождает акт, не зависящий от
сохранности основания; длящаяся пересчитывается непрерывно. Гражданство
конститутивно, освобождение от повинности длится.

### Цепочка возражений легла на вытеснение буквально

`intentio` → `exceptio` → `replicatio` оказалось не аналогией, а прямым
описанием отношения вытеснения: каждое следующее правило бьёт предыдущее,
порядок объявлен заранее. Отдельного механизма для исключений внутри одного
документа не понадобилось — вопрос снялся вместе с механизмом, который его
порождал.

Защита приобретённого при этом выражается **defeater**: `A4` ничего не выводит,
она только не даёт отнять. Отмена защиты есть удаление одного правила, после
чего `r_strip` перестаёт встречать сопротивление. В варианте с отрицанием то же
самое требовало отдельного нулевого предиката и перестановки порядка
вычисления.

### Период подтверждён как параметр, а не аргумент

Ни в одном правиле период не понадобился аргументом каждого предиката. Корпус
фиксируется на период, вывод идёт по срезу. Явный период нужен только там, где
проверяется прошлое состояние.

## Чего казус не показал

- **несовместимых пар должностей** — нужен казус про допуск к должности;
- **частичных статусов**: `peregrinus` с одним правом их лишь намечает;
- **знания человеком норм**: в правилах его нет и быть не должно. Знание влияет
  на то, подаст ли Марк прошение, а не на то, есть ли у него право. Значит оно
  живёт в модели человека, а не в корпусе, — полезное разграничение, полученное
  даром.

Схема предикатов проверена одним сценарием. Это существенное ограничение: она
достаточна для первого среза и не проверена ни на чём другом.
