# Схема предикатов

Единственное место, где перечислено всё, чем корпус вправе оперировать. Собрана
из пяти разобранных казусов. До появления
[[docs/design/components/scenario|загрузчика]] проверяется только чтением, и это видно:
раздел «известные дефекты» ниже — прямое следствие.

Роли четыре:

- **факт** — хранится с провенансом, приходит из сценария или порождается делом;
- **объявление** — данные корпуса: пучки, компетенции, уровни, требования;
- **вывод** — получается правилом и потребляется другими правилами;
- **выход** — вывод, который потребляет не корпус, а линтер, отчёт или дело.

Роль у предиката одна. Аргументы в таблицах ниже названы сортами — человек,
должность, период, — и загрузчик проверяет сорт каждой позиции.

## Выходы

Выход отличается от мёртвого вывода только тем, что объявлен выходом. Без такого
объявления загрузчик обязан сообщить о нём как о выводе, который никто не
потребляет.

## Предикаты-области

Порождаются загрузчиком из объявлений сценария, в корпусе не пишутся:
`person/1`, `office/1`, `status_kind/1`, `right/1`, `action_kind/1`,
`duty_kind/1`. Служат телом правил по умолчанию и опорой переменной «любое
значение».

## Форма правил

Соглашение, по которому загрузчик отличает ошибку от допустимой записи. Принято
автором; рассмотренные варианты и доводы —
`git show 5a4408d:docs/proposals/loader-blockers.md`.

**Терм** — переменная или константа. Составных термов нет: содержание обязанности
— отдельный аргумент «предмет», установленное — аргумент «о ком», акт ссылается на
другой акт идентификатором. Константы объявлены: права, виды действий, статусы,
должности, люди, идентификаторы фактов, параметры сценария вроде `limit`.
Константа `none` означает «неприменимо» и допустима только в позициях, где схема
это объявляет, — например срок обязанности-состояния.

**Текущий период** — встроенный терм `now`. Вычислитель подставляет номер периода
среза. Другие моменты правило видит только через хранимые даты и интервалы;
открытый интервал закрывается `now` при чтении фактов, поэтому константы `open` в
выводе нет.

**Безопасность.** Каждая переменная головы встречается в литерале предиката в
теле — утверждающем или отрицающем: отрицание здесь вывод, а не неудача, — либо на
выходе встроенного литерала со связанными входами. `now` связан всегда. Исключений
нет.

**Правило по умолчанию** — не исключение из безопасности. Его тело — предикаты-
области или смысловая опора:

```
r_nocomp   office(Off), action_kind(Kind)       ⇒ ¬competent(Off, Kind)
r_unborne  duty(P, _, K, _, maintain, none)     ⇒ ¬borne(P, K, now)
```

**Анонимная переменная** допустима только в теле. «Любое значение» в голове —
переменная с предикатом-областью: `action_kind(K) ⇒ ¬competent(Off, K)`.

**Встроенные литералы** — закрытый список: сравнения `<`, `=<`, `>`, `>=` над
связанными аргументами; `minus(A, B, C)` и `plus(A, B, C)` над номерами периодов —
связывают `C`, если связаны `A` и `B`. В аргументах предикатов выражений нет:

```
r_tenure   served(P, F, T), minus(T, F, D)      ⇒ tenure(P, D)
```

Сложение добавлено к «сравнению и вычитанию» из
[[docs/decisions/norms-are-inference-rules|решения о правилах]]: без него срок
`N0 + limit` и вторичная обязанность со сроком в следующем периоде невыразимы.

**Завершимость.** Результат `plus` или `minus` не может по циклу зависимостей
предикатов вернуться во вход того же литерала — такое правило является ошибкой.
Вместе с отсутствием составных термов и конечностью констант это делает вывод
конечным при любом корпусе игрока.

## Известные дефекты

Список существует ради смоук-теста: **загрузчик считается готовым, когда выдаёт
эти ошибки и замечания сам**, а не когда его написали. Казусы остаются в исходной
записи как фикстура и заведомо его не проходят, и это ожидаемо.

У каждого дефекта есть слаг: на них ссылаются из других документов.

**Ссылки в никуда**

- `resolved-undefined` — `resolved/1` употребляется в `r_decide` под
  отрицанием, нигде не выводится и не является фактом;
- `about-undefined` — `about/3` употребляется в `r_offense`, нигде не определён;
- `held-at-undefined` — `held_at/3` употребляется в `r_iter_seq`, нигде не
  определён;
- `reviewable-rule-missing` — `r_reviewable` участвует в отношении вытеснения
  казуса о децемвирате (`r_noreview > r_reviewable`), а правила с таким именем
  нет;
- `reviewable-never-derived` — `reviewable/1` отрицается в `r_noreview`,
  положительно не выводится ничем;

**Мёртвые выводы**

- `valid-unconsumed` — `valid/1` выводится `r_act_ok` и не потребляется ничем;
- `unconsumed-rights` — `ius_commercii` и `ius_conubii` выводятся в обоих
  казусах как права и не входят ни в одно условие. Провал `empty-right` внутри
  собственного примера.

**Расхождение арности**

- `duty-arity-mismatch` — в правилах первого казуса у `duty` четыре аргумента
  (`duty(P, munus, maintain, _)`), в `r_expire` пять, в этой схеме объявлено
  шесть — с адресатом и предметом. **Адресат не появляется ни в одном правиле**, хотя решение
  об обязанностях называет его тем, что определяет, кто вправе начать дело;
- `min-age-arity-mismatch` — `min_age` объявлен как `min_age/1` и употребляется
  функцией внутри сравнения `N - B < min_age(Off)`. Здесь исправлен на
  `min_age/2`, но правило `r_age` не переписано.

**Нарушения безопасности правил**

- `unbound-head-variable` — `r_age`: `Off` не связан положительным литералом;
  `r_lift`: `R` не связан;
- `anonymous-variable-in-head-rules` — `r_susp`, `r_veto`, `d_exempt`, `r_munus`
  — анонимная переменная в голове;
- `period-variable-unbound` — `r_viol_m`: `N` встречается только под
  отрицанием; `r_viol_a`: `N` не связан и уходит во встроенное сравнение.

**Функциональные символы**

- `compound-terms-in-heads` — `penalty(munus)`, `decide(Pt)`, `veto_of(Q, A)`,
  `tenure_confirmed(marcus)` — составные термы, причём первые три **строятся в
  голове из переменных**. А вычислитель гарантирует завершимость «на конечных
  данных, отсутствие функциональных символов».

**Прочее**

- `limit-undeclared` — `limit` в `r_decide` не объявлен нигде;
- `open-interval-arithmetic` — `r_tenure` считает `To - From`, где `To` может
  быть константой `open`;
- `duplicate-iteration-rule` — `r_iter` и `r_iter_abs` — одно правило под двумя
  именами в разных казусах;
- `fact-and-conclusion` — `in_force/2` объявлен фактом, а `r_veto` выводит
  `¬in_force(A, _)`: предикат одновременно хранится и выводится опровержимым
  правилом.

**Найдены прототипом загрузчика** — чтение их пропустило:

- `a4-unbound-head` — `d_a4 ⇝ status(P, S)` с телом `norm_in_force(a4)`: `P` и
  `S` не связаны;
- `expire-unbound` — децемвират: у `r_expire` анонимная переменная в голове, у
  `r_expire` и `r_viol` период `N` не связан;
- `counter-veto-arity` — `r_counter` выводит `¬in_force` с одним аргументом;
- `held-negation-never-concluded` — `r_prior` требует `¬held(P, Prev)`, но
  отрицательный вывод `held` не даёт ни одно правило. Отрицания по неудаче нет,
  поэтому ценз «прежняя должность» не срабатывает никогда: нужен умолчание
  `¬held`, вытесняемое `r_held`. Тот же род у `¬resolved` в `r_decide`;
- `adopt-defeat-without-conflict` — `r_adopt > r_adopt_out` объявлен между
  правилами, которые не спорят: `status(P, plebeius)` и `¬status(P, patricius)`;
- `status-grant-revoke-unordered` — выдача статуса (`r_status`, `r_born`,
  `r_edict`, `r_adopt`) не упорядочена с лишением (`r_revoke`, `r_strip`).
  Лишённый статуса получит non liquet, а не отсутствие статуса;
- `same-polarity-deadlock` — казус о коллегах обещает тупик между `r_veto` и
  `r_counter` и между `r_iter_abs` и `r_iter_seq`. Но эти пары выводят одно и то
  же по знаку и не спорят: вывода не будет из-за формы правил, а не из-за
  необъявленного порядка. Настоящий спор повторения — с `r_elig`;
- `ultra-vires-argument-order` — `r_ultra` сопоставляет `performed(Act, _, Off,
  Kind)`, где вид действия стоит на месте предмета. Загрузчик этого не видит:
  сорта позиций он пока не проверяет.

## Что выдаст загрузчик

По соглашению о форме правил. **Ошибка** — вычисление невозможно, **замечание** —
корпус загружен и плох.

| Дефект | Что выдаст загрузчик |
| --- | --- |
| `resolved-undefined`, `about-undefined`, `held-at-undefined` | ошибка: предикат не объявлен |
| `reviewable-rule-missing` | ошибка: ссылка на несуществующее правило |
| `reviewable-never-derived` | замечания: вывод только отрицательный и никем не потребляется |
| `valid-unconsumed` | замечание: мёртвый вывод |
| `unconsumed-rights` | замечание: право не входит ни в одно условие — и `ius_suffragii` тоже |
| `duty-arity-mismatch`, `min-age-arity-mismatch` | ошибка: другая арность |
| `unbound-head-variable` | ошибка: небезопасное правило |
| `anonymous-variable-in-head-rules` | ошибка: недопустимый терм |
| `period-variable-unbound` | ошибка: небезопасное правило, пока `N` не заменён на `now` |
| `compound-terms-in-heads` | ошибка: недопустимый терм |
| `limit-undeclared` | ошибка: ссылка на необъявленную константу |
| `open-interval-arithmetic` | исчезает: интервал закрывается при чтении фактов |
| `duplicate-iteration-rule` | замечание: два правила с одинаковыми головой и телом |
| `fact-and-conclusion` | замечание: у предиката две роли |
| `a4-unbound-head`, `expire-unbound` | ошибки: небезопасное правило, недопустимый терм, несвязанный встроенный литерал |
| `counter-veto-arity` | ошибка: другая арность |
| `held-negation-never-concluded` | замечание: отрицательное условие, которого не выводит ни одно правило |
| `adopt-defeat-without-conflict` | замечание: порядок между неспорящими правилами |
| `status-grant-revoke-unordered`, `same-polarity-deadlock` | замечания: спор без объявленного порядка — там, где он есть на деле |
| `ultra-vires-argument-order` | не ловится: нужна проверка сортов |

Кроме того, `established` с четырьмя аргументами даёт ошибку арности — следствие
соглашения, а не дефект казуса.

Отсюда смоук-тест: **исходные казусы дают ровно этот список**, а переписанные по
соглашению — загружаются и дают только замечания. В прототипе список закреплён
эталонным отчётом `internal/scenario/testdata/originals/report.golden`.
