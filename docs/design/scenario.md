# scenario — данные мира и их загрузчик

Компонент, с которого начинается код. Ни от чего не зависит и может делаться
раньше вычислителя.

## Зачем он первый

Сейчас схема предикатов, правила и отношение вытеснения живут прозой в пяти
разобранных казусах. Проза не проверяется, поэтому и не проверена: механический
разбор арностей за десять секунд нашёл в них пять дефектов, которых не увидело
внимательное чтение.

Загрузчик заставляет схему существовать **в одном месте и машинно**. Это его
главная работа, а не чтение файлов.

Второе: **его проверки и проверки [[docs/concepts/linter|линтера]] — один и тот
же код**. Загрузчик спрашивает у нашего сценария ровно то, что линтер спросит у
конституции игрока. Поэтому написать его сейчас — не расширение объёма, а первая
и третья вехи, придвинутые вперёд.

## Чего здесь нет

**Интерфейсов.** Загрузчик — функция от файлов к значению. Подстановки в нём не
наблюдается, а порты на будущее запрещены. Четыре шва проекта перечислены в
[[docs/guide/05-how-it-is-built|главе 5]], и этот компонент не входит ни в один.

**Парсера языка норм.** Правила приходят структурированными данными. Как только
захочется грамматику с приоритетами — сработало стоп-правило
[[docs/design/deduction|вычислителя]].

## Что подаётся на вход

Семь семей данных. Всё, что ниже, — данные сценария; механика живёт в коде.

**Символы.** Права, виды действий, предикаты с объявленной арностью. Одно место,
где перечислено всё, чем корпус вправе оперировать.

**Статусы.** Пучок прав, пучок обязанностей, наследуемость. Три поля, и все три
обязательны: статус, умеющий только давать, описывает половину случаев, а
наследуемость является свойством конкретного статуса, а не общим правилом.

**Должности.** Компетенции, срок — числом периодов либо до события, — требования
допуска, способность проверять, способ замещения. Плюс объявленные
несовместимости и запрет повторения.

**Документы и нормы.** Документ несёт уровень в иерархии. Норма несёт правило,
период принятия, период вступления и вид — конститутивная или длящаяся. Случай
«вступает раньше, чем принята» допустим: это ретроактивность, то есть содержание
игры, а не ошибка данных.

**Отношение вытеснения.** Пары правил с порядком. Плюс ограничения целостности —
комбинации выводов, объявленные недопустимыми, включая пятичастный запрет
разделения полномочий.

**Люди и начальные факты.** Идентичность и факты с провенансом.

**Точки расширения и пороги.** Условие акта (единолично, N из M, все), момент
проверки допуска, задание срока, выход из тупика, пороги линтера. Обоснование —
[[docs/decisions/extension-points-require-a-casus|критерий точек расширения]].

## Форма

Иллюстративно; конкретные имена появятся при реализации.

```go
type Scenario struct {
	StartPeriod Period
	Symbols     Symbols      // права, виды действий, предикаты с арностью
	Statuses    []Status
	Offices     []Office
	Documents   []Document
	Norms       []Norm       // норма несёт правило и даты
	Defeats     []Defeat     // пары правил с порядком
	Constraints []Constraint // недопустимые комбинации выводов
	People      []Person
	Facts       []Fact
	Options     Options      // точки расширения
	Thresholds  Thresholds   // пороги линтера
}

type Rule struct {
	ID       RuleID
	Head     Literal
	Body     []Literal
	Strength Strength // строгое | опровержимое | defeater
}

type Literal struct {
	Predicate PredicateID
	Args      []Term // переменная, константа или встроенное сравнение
	Negated   bool
}

type Defeat struct{ Over, Under RuleID }
```

Файлы — JSON: он в стандартной библиотеке, машинно проверяем и не требует
грамматики. Многословен, и это принимается: сценариев вручную будет два, и они
лежат в `testdata/` как обычные фикстуры. Авторский ввод появится вместе с
фронтом и будет **порождать** эти файлы, а не заменять их.

Если писать руками станет больно раньше фронта, допустима построчная форма с
фиксированной формой литерала, читаемая сканером. Границу держать жёстко: как
только понадобятся приоритеты операций или вложенность — это грамматика, и
компонент окончен.

## Что получается на выходе

```go
func Load(fsys fs.FS) (*Scenario, *Report, error)

type Report struct {
	Errors   []Finding // вычисление невозможно
	Findings []Finding // корпус загружен, но вот что с ним не так
}
```

Разделение на два списка существенно, и оно же определяет границу между
загрузчиком и линтером.

**Ошибка** — то, при чём вывод невозможен в принципе: неизвестный предикат,
несовпадение арности, небезопасное правило, ссылка в никуда, цикл в отношении
вытеснения, встроенный предикат с несвязанными аргументами.

**Замечание** — то, при чём корпус прекрасно загружается и является плохой
конституцией. Загрузчик почти ничего не отвергает: **испорченная конституция
игрока обязана загружаться**, иначе игра не сможет показать провал.

## Проверки

Ошибки — их шесть, и все механические:

1. предикат не объявлен либо употреблён с другой арностью;
2. правило небезопасно: переменная головы не связана положительным литералом
   тела;
3. встроенный предикат с несвязанными аргументами;
4. ссылка на несуществующее правило, документ, статус, должность или право;
5. цикл в отношении вытеснения;
6. у статуса не объявлены оба пучка либо наследуемость.

Замечания — начало каталога, и это те же проверки, что у линтера:

- предикат употребляется в теле, но не выводится и не является фактом —
  недоопределённое условие;
- предикат выводится, никем не потребляется и не объявлен выходом наружу —
  семейство пустого права;
- правило, всегда проигрывающее спор;
- норма вступает раньше, чем принята, — ретроактивность;
- пара правил с противоположными выводами без объявленного порядка.

Остальное из [[docs/guide/04-what-goes-wrong|каталога]] требует графа власти или
журнала и приходит позже.

## Порядок реализации

Наименьшее полезное первым; после каждого шага что-то работает.

1. **Символы и арности.** Ничего не загружает, кроме объявлений, и уже ловит
   две ошибки из шести;
2. **Факты** с провенансом;
3. **Правила** и проверка безопасности;
4. **Вытеснение** и проверка цикла;
5. **Статусы, должности, документы, нормы**;
6. **Замечания** — пять проверок выше.

Смоук-тест готовности: оба разобранных казуса —
[[docs/design/casus-citizenship|гражданство]] и
[[docs/design/casus-office-eligibility|допуск к должности]] — загружаются, а
известные дефекты в них появляются как замечания, а не как сюрприз при чтении.

## Чего компонент не делает

Не вычисляет: вывод принадлежит [[docs/design/deduction|deduction]]. Не знает,
какой документ выше: приоритет живёт в [[docs/design/entitlement|entitlement]].
Не хранит: `facts` и `corpus` владеют состоянием во время партии, а сценарий
только даёт им начальное значение.
