# storage

## Назначение

Заменить хранение в памяти реальным адаптером, не меняя семантику фиксации.

## Владеет

Ничем в домене. Контракт фиксации определён решением
[[docs/decisions/durable-commit-is-a-semantic-contract|durable-commit-is-a-semantic-contract]].

## Предоставляет

Не спроектировано.

## Требует

- `facts` — что хранить;
- `journal` — что хранить.

## Не знает

Провайдера — в слое дизайна; выбор провайдера лежит в
[[docs/impl/README|реализации]] и выбрасывается без последствий для этого слоя.

## Исходы и ошибки

Минимальная матрица контракта: конфликт версий, неизвестный исход после
таймаута, падение после commit, дублирующая доставка, повтор, сверка зависших
намерений, порядок в пределах одного ключа.

## Шов

**Да**: память против реального адаптера.

## Проверяется

Один набор контрактных тестов для реализации в памяти и для каждого реального
адаптера — гейт вехи [[docs/design/stages/durable-storage|durable-storage]]. См.
[[docs/design/testing|testing]].

## Открыто

Каким контекстам нужен event sourcing, а каким достаточно состояния и журнала —
см. [[docs/open-questions|открытые вопросы]].
