# linter

## Назначение

Проверить корпус до хода на провалы, которые являются свойством написанного, а
не случившегося.

## Владеет

Проверки из [[docs/guide/04-what-goes-wrong|каталога провалов]], помеченные
«линтер», и пороги к ним как данные сценария. См.
[[docs/concepts/observation#Линтер конституции|линтер конституции]].

Инварианты:

- работает без вызовов модели, детерминированно;
- **пороги — данные, проверки — код**;
- не сравнивает уровни документов сам: спрашивает, есть ли случаи с
  неопределённым или противоречивым результатом;
- **вправе считать** — в отличие от вычислителя. Требования к составу органа
  выражаются ограничением целостности, которое считает линтер.

## Предоставляет

**Игровой `Finding` принадлежит линтеру.** Он строится из диагностик
[[docs/design/components/deduction|deduction]] и
[[docs/design/components/scenario|scenario]], которые предметной области игрока не
несут, из пересчёта [[docs/design/components/impact|impact]] и из графа
[[docs/design/components/power-graph|power-graph]].

В прототипе — `internal/linter`:

```go
func Lint(in Input) (*Report, error)

type Input struct {
	Corpus   corpus.Version
	Roles    map[string]deduction.Role
	Facts    []facts.Fact
	Strategy entitlement.Strategy
	Now      period.Period
	Loader   []deduction.Diagnostic // отчёт загрузчика, если корпус загружен
	Before   *corpus.Version        // версия до правки; nil — пересчитывать нечего
}

type Finding struct {
	Failure string  // слаг каталога; пусто — замечание формы вне каталога
	Code    string  // проверка или диагностика, давшая замечание
	Channel Channel // linter или recount
	Place   string
	Message string
	People  []string
}
```

`Report` несёт ошибки, замечания, пересчёт и граф периода. Форма `Finding` —
решение помощника, ждёт автора; мера, порог и окно из кандидата не понадобились ни
одной проверке среза.

## Требует

- `corpus` — что проверять;
- `deduction` — анализ графа правил;
- `impact` — ретроактивность и затронутые правкой;
- `power-graph` — проверки на графе власти.

## Не знает

Уровней документов и их приоритета — это внутри
[[docs/design/components/entitlement|entitlement]].

## Исходы и ошибки

Ошибки — те же, что у загрузчика и вычислителя: с ними срез не разрешается, и
проверки, которым нужен вывод, пропускаются. Замечания не останавливают ничего:
испорченный корпус живёт.

## Шов

Нет.

## Проверяется

Прототип — `internal/linter/linter_test.go`, эталоны в `internal/linter/testdata`.
Каждая проверка графа и пересчёта имеет контроль, на котором молчит:

- ретроактивная правка `C1` в периоде 35 с силой от 28 — `retroactivity` с Марком
  поимённо; та же правка без обратной силы — ни замечания, ни затронутых;
- отмена `A4` после нормы `N5` — `taking-of-vested` с Марком;
- казус о допуске в периоде 13 — `circumventable-condition` через `adrogatio`
  цензора, `closed-eligibility` цензора, `review-dead-end`; без компетенции
  `adrogatio` — вместо них `competence-gap`;
- трибун на месте делает претора пересматриваемым, пустой трибунат — нет; так же
  занятый пересматривающий консул, а два цензора с кворумом сдерживают друг друга и
  снимают обходимость допуска;
- взаимный пересмотр консула и претора — `review-cycle`;
- единственный претор в периоде 31 — `judge-in-own-cause` на Гае, второй претор
  его снимает;
- всё это на обеих стратегиях разрешения норм.

Отчёт по сценарию — `go run ./cmd/lint -now N [-without норма] [-graph] schema.json scenario.json`.

## Открыто

- **Форма `Finding`** принята помощником для прототипа, см.
  [[docs/proposals/prototype-decisions|журнал решений]].
- Проверки, общие с загрузчиком, живут в коде `deduction`; загрузчик и линтер их
  только вызывают. Ретроактивность загрузчик пока тоже сообщает — линтер заменяет
  это замечание своим, с пересчётом.

## Состав проверок

Проверки вехи [[docs/design/stages/corpus-checks|corpus-checks]]:
`retroactivity`, `underdetermined-condition`, `delegated-discretion`,
`empty-right`, `duty-without-consequence`, `ladder-without-last-step`,
`norm-nobody-applies`, `impossible-duty`, `competence-gap`, `review-dead-end`,
`review-cycle`, `dangling-succession`, цикл в отношении вытеснения.

Несовместимость бывает двух родов, и линтер обязан различать обе: объявленную
(`incompatible`) и структурную — держащуюся на том, что права разведены по
статусам. См. [[docs/design/casus/office-eligibility|казус о допуске]].

### Что есть в прототипе

| Провал | Откуда | Как считается |
| --- | --- | --- |
| `underdetermined-condition` | `deduction` | условие, которое не выводит ни одно правило и не даёт ни один факт; отрицательное условие без отрицательного вывода |
| `dead-conclusion` | `deduction` | вывод, который не потребляет ни одно правило и который не объявлен выходом |
| `indeterminacy` | `deduction` | спор без объявленного порядка — только эта часть провала |
| `empty-right` | `scenario` | право не входит ни в одно условие и ни в одно требование должности — только эта часть провала |
| `retroactivity` | `impact` | норма действует раньше принятия; пересчёт в окне от вступления до принятия называет затронутых |
| `taking-of-vested` | `impact` | правка отняла статус или доказала его отсутствие в текущем периоде |
| `competence-gap` | граф | вид действия в условии `competent/2` или акт, на который опирается условие, без должности; вид акта берётся по исходу, если условие его называет |
| `review-dead-end` | граф | должность с компетенциями без действующего входящего сдерживания — intercessio, пересмотра или согласия коллег |
| `review-cycle` | граф | должности пересматривают друг друга по кругу |
| `dangling-succession` | объявления | нет способа замещения или цепочка назначающих не доходит до учредительной должности |
| `judge-in-own-cause` | граф | вид решения, который в периоде может вынести ровно один человек |
| `duty-without-consequence` | правила | осуждение за вид обязанности не ведёт ни к одному правилу |
| `ladder-without-last-step` | правила | последствия кругом возвращаются через обязанности и не доходят до конечного акта |
| `norm-nobody-applies` | граф и корпус | нарушения обязанностей выводятся, а занятой должности, вправе проверять и со способностью, нет — только должностной путь |
| `unchecked-act` | граф и `deduction` | вид акта, от которого зависит статус или допуск, без останавливающего вида действия, у несдерживаемой должности |
| `circumventable-condition` | граф и `deduction` | допуск опирается на акт должности, которую ничто действующее не сдерживает |
| `closed-eligibility` | граф | цикл по рёбрам допуска |

Прочие замечания анализа графа правил — двойная роль предиката, дубликат правила,
порядок между неспорящими, вечно вытесненное правило, вывод только отрицательный
— идут без слага, как замечания формы.

Чего проверки не видят:

- **`review-dead-end` верит объявлениям.** Пересмотр и согласие объявлены у
  должности, но в ходе дела обжалования нет: граф говорит, что пересмотр возможен,
  а партия его не разыгрывает;
- **`competence-gap` видит вид действия, только если условие называет исход**
  решения: `decision(D, C, guilty, _, _)` требует суда, а `decision(_, Pt, _, _, _)` —
  любого вида, которым решение выносится;
- **допуск грубый**: акт открывает допуск во все должности с требованием права,
  без сверки, какой статус даст акт.
