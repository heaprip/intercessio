# agenda — повестка законодателя

Основание —
[[docs/decisions/player-works-a-stack-of-proposals|player-works-a-stack-of-proposals]].
Владелец выбран помощником и ждёт автора — P39 в
[[docs/proposals/prototype-decisions|журнале решений]].

## Назначение

Собрать стопку карточек, которую auctor разбирает между периодами: что из прожитого
стоит решения о законе, в каком порядке и что может вернуться.

## Владеет

**Стопка и карточка** — [[docs/concepts/game#Стопка|стопка]],
[[docs/concepts/game#Карточка|карточка]].

Инварианты:

- **отбор детерминирован**: модель может пересказать карточку, но не выбирает её;
- **у карточки есть свидетельство** — находки и записи журнала, из которых она
  собрана; без него карточка не собирается;
- **не попавшее в стопку не теряется** — уходит в переполнение для отчёта;
- **решённая карточка возвращается с новым свидетельством**; отклонённая —
  ещё и напоминанием после тишины, заданной пресетом; принятая, чья находка
  осталась, — сразу.

## Предоставляет

В прототипе — `internal/agenda`:

```go
func Build(in Input) Stack

type Input struct {
	Lint    *linter.Report
	Entries []journal.Entry // прожитого периода
	Corpus  corpus.Version
	Now     period.Period
	Memory  Memory // решённые карточки
	Preset  Preset // размер стопки и веса провалов
}

type Stack struct{ Cards, Overflow, Held []Card }

func (m Memory) Record(c Card, now period.Period, accepted bool) Memory
```

Карточка — ключ корня, провал, корень, охват, люди, свидетельство, счёт и
предложение: текст и, если правка механическая, готовые правки для хода.

## Требует

- `linter` — находки корпуса;
- `journal` — события прожитого периода;
- `corpus` — чтобы составить предложение правки;
- `turn` — форма правки, которую принимает ход.

## Не знает

Как auctor решает карточку и кто пишет текст предложения: советник-модель не
спроектирован.

## Исходы и ошибки

Ошибок нет. Пустая стопка — нормальный исход, и о нём стоит спросить: решение о
стопке требует пересмотра, если в ней нечего решать.

## Шов

Нет.

## Проверяется

Веха [[docs/design/stages/stack-of-proposals|stack-of-proposals]]: партия четырёх
периодов на игровой фикстуре, где правки приходят только через стопку.

## Открыто

- **советник-модель** — роль и владелец не решены; в прототипе предложение по
  шаблону;
- **карусель напоминаний**: пустеющую стопку сменила карусель — отклонённое
  возвращается по кругу каждые несколько периодов. Нужно ли гасить карточку,
  отклонённую много раз, не решено;
- **журнальные паттерны отсева** из черновика — `circumvention-realized`, тихие
  провалы — не сделаны;
- как стопка соотносится с находками практики цензора.

## Устройство

### Откуда карточки

Находки линтера, у которых есть провал из каталога; замечания о форме корпуса в
стопку не идут. События прожитого периода: конфликт интересов, жалобы после правки,
non liquet по основанию.

### Корень

Находки, которые одна правка закрыла бы разом, — одна карточка. Споры без порядка
группируются по предикату: десять пар правил, спорящих о статусе, — одна карточка
с охватом десять. Остальное — по месту находки.

### Порядок и размер

Счёт — вес провала, умноженный на охват. Веса по слагам и размер стопки — данные
пресета.

### Предложение

Шаблон. Механическая правка есть только у ретроактивности — переиздать норму с
силой от даты принятия; остальные карточки говорят, что сделать, а норму пишет
auctor.
