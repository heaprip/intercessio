# Варианты ответов на блокеры загрузчика

Статус: НЕ ПРИНЯТО  
Предложено: помощник, по просьбе автора  
Трогает: [[docs/design/predicate-schema|схему предикатов]], раздел «Не решено» [[docs/design/README|спины архитектуры]], карточки [[docs/design/components/scenario|scenario]], [[docs/design/components/deduction|deduction]], [[docs/design/components/linter|linter]]  
Опирается на: [[docs/decisions/norms-are-inference-rules|norms-are-inference-rules]], `spike/legal-engine`

Восемь вопросов, без ответа на которые загрузчик не отличит ошибку от допустимой
записи: пять — о форме правил, три — о владении. У каждого варианты, цена и
рекомендация помощника. Выбирает автор; выбранное переносится в схему предикатов и
карточки, а черновик удаляется. Если автор сочтёт форму термов сквозным и дорого
обратимым выбором, её стоит оформить решением.

## Итог в одном месте

Рекомендации складываются в один язык правил. Ни одно принятое решение он не
переписывает; одно место расширяет — список встроенных предикатов, см. вопрос 3.

| Вопрос | Рекомендация |
| --- | --- |
| `period-in-rules` | встроенный терм `now` — текущий период среза |
| `default-rule-safety` | правило по умолчанию получает тело из предикатов-областей, как в `spike/legal-engine` |
| `head-arithmetic` | в аргументах только переменные и константы; счёт — встроенными литералами тела; запрет рекурсии через счёт |
| `compound-terms` | запрещены; содержание — отдельным аргументом, акты — идентификаторами |
| `anonymous-head-variable` | запрещена; «любое» — предикатом-областью, «неприменимо» — константой `none` |
| типы правил | владеет `deduction`; `scenario` требует `deduction` |
| `Finding` | у загрузчика и вычислителя свои диагностики; игровой `Finding` — позже, у линтера |
| `scenario` и `corpus`, `facts` | `scenario` требует `corpus` и `facts` |

Термы тогда — только переменная или константа. Вычислитель остаётся плоским
Datalog с вытеснением и счётом над периодами, и завершимость следует из конечности
констант и одной статической проверки.

## 1. Период в правилах

**Что сейчас.** Решение объявляет период параметром вычисления, а не аргументом
предикатов. Но в казусах `N` — свободная переменная: `F =< N, N =< T` в `r_susp` и
`r_incompat`, `N =< M` в `r_suspend`, `N > D` в `r_viol_a`, `N - B` в `r_age`. В
головах тоже: `violated(P, K, N)`, `¬borne(P, K, N)`.

**Варианты.**

- **A. Встроенный терм `now`.** Нульарный терм, который вычислитель подставляет
  номером периода среза. Для проверки безопасности он связан, как константа. Запись
  явная: `occupies(P, O1, F, T), F =< now, now =< T`. Это снимочная семантика
  темпоральных баз данных: запрос вычисляется на срезе одного момента, интервалы —
  способ хранения, а не предмет вывода.
- **B. Неявная переменная `N` по соглашению.** То же, что A, но зарезервированное
  имя переменной. Сталкивается с переменными игрока, а загрузчику нужно особое
  правило «эта переменная связана».
- **C. Период — явный аргумент каждого предиката.** Полный темпоральный Datalog.
  Противоречит принятому решению — нужна замена. Правила вида `p(N + 1) ⇐ p(N)`
  дают бесконечный вывод без горизонта, а каждое правило удлиняется.

**Рекомендация — A.** Совпадает с принятым решением буквально, и стык
`entitlement` и `deduction` становится контрактом: вычисление получает `now` как
вход. Открытый интервал `served(P, 5, open)` закрывается текущим периодом при
чтении фактов — это уже записано в карточке `facts`, — поэтому вычислитель
константы `open` не видит, и `open-interval-arithmetic` исчезает.

Цена: правило не может рассуждать о другом периоде, кроме как через хранимые
интервалы и даты. `held_at(P, Off, N-1)` в `r_iter_seq` переписывается через
`occupies(P, Off, F, T)` и сравнение `T` с `now` — см. вопрос 3.

## 2. Правило по умолчанию и безопасность

**Что сейчас.** `r_nocomp ⇒ ¬competent(Off, Kind)` и `r_unborne ⇒ ¬borne(P, K, N)` —
пустое тело и переменные в голове. Решение называет это штатным приёмом
закрытости мира, а проверка безопасности, которую пишет тот же вычислитель, это
запрещает.

**В `spike/legal-engine` вопрос уже решён**: там `r_nocomp` записан с телом
`office(Off), action_kind(Kind)` — и `vested-protection` так же держит `d_a4` на
`person(P), status_kind(S)`. Казусы этого не переняли.

**Варианты.**

- **A. Тело из предикатов-областей.** Загрузчик порождает одноместные предикаты
  из объявлений сценария: `office/1`, `action_kind/1`, `person/1`, `status_kind/1`,
  `right/1`, `duty_kind/1`. Правило по умолчанию пишет их явно:
  `office(Off), action_kind(Kind) ⇒ ¬competent(Off, Kind)`. Правило безопасности
  одно, без исключений; вывод конечен. Там, где у умолчания есть смысловая опора,
  лучше она, а не голая область: `duty(P, K, maintain, D) ⇒ ¬borne(P, K, now)` —
  «не исполнено» имеет смысл только там, где обязанность лежит.
- **B. Сорта в схеме, опоры подставляет загрузчик.** У каждой позиции предиката
  объявлен сорт — схема уже называет аргументы «человек», «должность». Для
  несвязанной переменной загрузчик сам добавляет предикат-область. Запись в казусах
  остаётся прежней, но в трассе появляются посылки, которых нет в тексте нормы.
- **C. Исключение для умолчаний: небезопасное отрицательное правило вычисляется
  по запросу.** Так работает конструктивное отрицание в s(CASP). Ломает прямой
  вывод до неподвижной точки и анализ графа, на котором стоят проверки линтера.
- **D. Закрытость мира через отрицание по неудаче.** Противоречит принятому
  решению: исключение выражается вытеснением, а не отрицанием.

**Рекомендация — A**, с сортами из B только для проверки типов, без подстановки:
загрузчик сообщает «в позиции должности стоит человек», но опор не добавляет. Цена
— многословие правил по умолчанию; зато их всего несколько, и каждое честно
показывает, над чем берётся умолчание.

## 3. Арифметика в голове

**Что сейчас.** `tenure(P, To - From)`, `duty(praetor, decide(Pt), achieve, N0 + limit)`,
`duty(P, penalty(munus), achieve, N + 1)` — счёт в позиции аргумента головы;
`N - B < min_age(Off)` — функция внутри сравнения; `held_at(P, Off, N-1)` — счёт в
аргументе тела.

**Варианты.**

- **A. Счёт — только встроенными литералами тела с выходом.** `minus(A, B, C)` и
  `plus(A, B, C)`: при связанных `A` и `B` литерал связывает `C`. В аргументах
  предикатов только переменные и константы. `served(P, F, T), minus(T, F, D) ⇒
  tenure(P, D)`. Проверка безопасности расширяется одной строкой: выход встроенного
  литерала связан, если связаны входы. Каждый шаг счёта виден в трассе.
- **B. Выражения в аргументах головы над связанными переменными**, как в gringo и
  Soufflé. Короче запись; безопасность требует связанности всех переменных
  выражения.

**Завершимость не зависит от выбора между A и B.** `plus(D, 1, E), p(D) ⇒ p(E)`
так же бесконечен, как `p(D + 1) ⇐ p(D)`; Soufflé прямо отказывается от гарантии
завершимости, как только разрешает арифметические функторы. А решение обещает, что
игрок не напишет нормы, из-за которой ход не закончится. Нужна одна из двух
защит:

- **статическая проверка**: результат счёта не может по циклу зависимостей
  предикатов вернуться во вход того же счёта. Загрузчик сообщает это ошибкой. Граф
  правил вычислитель и так анализирует;
- **ограниченная область**: встроенный литерал порождает только периоды в
  диапазоне от начала партии до `now` плюс горизонт. Проще, но молча обрезает
  ошибку игрока.

**Рекомендация — A со статической проверкой.** Один вид литерала для всего счёта,
ошибка видна до хода, а не прячется обрезкой.

Цена, которую решает автор: **сложение расширяет закрытый список встроенных
предикатов.** Решение называет минимумом «сравнение и вычитание над номерами
периодов»; срок `N0 + limit` и вторичная обязанность `N + 1` без сложения
невыразимы. Это расширение списка, а не замена решения, но оно должно быть
названо.

Попутно: `limit` должен быть объявлен — как параметр сценария или свойство
должности; `min_age(Off)` становится литералом `min_age(Off, A)` в теле.

## 4. Составные термы

**Что сейчас.** `penalty(munus)`, `decide(Pt)`, `veto_of(Q, A)` строятся в голове,
последние два — из переменных; `tenure_confirmed(P)` сопоставляется в теле `r_c1`.
Вычислитель гарантирует завершимость «при отсутствии функциональных символов».

**Варианты.**

- **A. Запрещены.** Терм — переменная или константа. Содержание уходит отдельным
  аргументом: `duty(praetor, decide, Pt, achieve, D)` — у обязанности появляется
  предмет; `established(f1, tenure_confirmed, marcus, censor, 30)`. Вето на вето
  перестаёт быть термом: вето — это акт, у акта есть идентификатор, и
  `vetoes(P, V)` ссылается на идентификатор первого вето. Идентификаторы у фактов
  уже есть.
- **B. Плоские конструкторы.** Конструктор объявлен в схеме с арностью, строится из
  связанных переменных, но **вложенность запрещена**. Множество термов остаётся
  конечным — конструкторы × константы в степени арности, — и завершимость
  сохраняется без анализа. Цена: терм в Go становится рекурсивным типом, появляется
  сопоставление по образцу, а вето на вето всё равно невыразимо без вложенности.
- **C. Неограниченные функциональные символы.** Ломает завершимость; отпадает.

**Рекомендация — A.** Самый простой тип терма, трасса и шаблоны прочтения читаются
по позициям, линтеру не нужно заглядывать внутрь термов. Работа по заземлению
правил аргументации через Datalog ставит те же два ограничения — переменные головы
в теле и отсутствие функциональных символов. Цена: `duty` получает шестой
аргумент — предмет, и `duty-arity-mismatch` нужно чинить сразу с этим. Если
плоская запись окажется уродливой больше чем в двух казусах, вернуться к B.

## 5. Анонимная переменная в голове

**Что сейчас.** `_` в голове несёт три разных смысла:

- «для любого вида» — `r_susp ⇒ ¬competent(Off, _)`;
- «неприменимо» — срок у обязанности-состояния в `r_munus` и `d_exempt`;
- «в любом периоде» — `r_veto ⇒ ¬in_force(A, _)`.

**Варианты.**

- **A. Запрещена.** «Любое» — переменная с предикатом-областью:
  `action_kind(K) ⇒ ¬competent(Off, K)`. «Неприменимо» — объявленная константа
  `none`, и схема говорит, в каких позициях она допустима. «В любом периоде»
  исчезает вместе с вопросом 1.
- **B. `_` в голове означает «любое значение».** Вывод становится неосновным, спор
  между `¬competent(Off, _)` и `competent(Off, K)` требует унификации, множество
  выводов перестаёт быть множеством основных фактов. Отпадает.
- **C. Загрузчик разворачивает `_` в переменную с предикатом-областью.** Неявно:
  тот же довод, что против подстановки опор в вопросе 2.

**Рекомендация — A.** Совпадает с ответом на вопрос 2, три смысла становятся тремя
разными записями.

**Найдено по пути:** `in_force/2` объявлен фактом, а `r_veto` выводит
`¬in_force(A, _)`. Предикат одновременно хранится и выводится опровержимым
правилом. Кандидат в семнадцатый дефект — `fact-and-conclusion`; загрузчику нужна
проверка «роль предиката одна».

## 6. Типы правил

**Что сейчас.** `Rule`, `Literal`, `Defeat` определены в карточке `scenario`, нужны
`deduction`, и оба объявлены листьями.

**Варианты.**

- **A. Владеет `deduction`; `scenario` требует `deduction`.** Карточка вычислителя
  уже владеет семантикой, проверкой безопасности и анализом графа правил. Вычислитель
  остаётся листом и проверяется синтетическими программами без предметной области.
- **B. Отдельный компонент — словарь правил.** Оба требуют его. Чисто, но это
  двадцать первая карточка, а пакет из одних типов близок к запрещённому `models`.
- **C. Владеет `scenario`; `deduction` требует `scenario`.** Вычислитель начинает
  зависеть от формата данных мира — статусов, должностей, — и синтетические
  программы тянут за собой сценарий. Отпадает.

**Рекомендация — A.** Следствие для вех: `scenario-loader` идёт раньше `derivation`,
поэтому типы правил и проверка безопасности пишутся в пакете вычислителя в самом
начале работы над загрузчиком, без вычисления. Веха зависит от типов компонента, а
не от готовности вехи.

## 7. `Finding` и общие проверки

**Что сейчас.** `Finding` записан за линтером, а загрузчик выполняет те же
проверки; линтер требует `corpus`, `deduction`, `impact` и `power-graph`.

Разбор шести ошибок и пяти замечаний загрузчика по тому, кто их на деле умеет:

| Проверка | Чья |
| --- | --- |
| предикат не объявлен или другая арность | схема — `scenario` |
| небезопасное правило, встроенный с несвязанными аргументами, цикл вытеснения | `deduction` |
| ссылка на несуществующее, у статуса нет пучков | `scenario` |
| недоопределённое условие, мёртвый вывод, вечно вытесненное правило, спор без порядка | анализ графа — `deduction` |
| ретроактивность | даты норм — `scenario`, позже `impact` |

**Варианты.**

- **A. У каждого производителя своя диагностика, игровой `Finding` — позже.**
  `deduction` возвращает диагностику без предметной области: слаг, идентификаторы
  правил и предикатов. `scenario` — свою, со ссылками на объекты сценария, и
  собирает обе в свой отчёт. `Finding` игрока — провал, слой, канал, место, трасса,
  мера и порог, окно, как в удалённом черновике о стопке, — появляется у линтера на
  вехе `corpus-checks` и строится из этих диагностик. «Один и тот же код» при этом
  соблюдён: проверки живут в `deduction`, их вызывают и загрузчик, и линтер.
- **B. Один `Finding` у линтера, загрузчик требует линтер.** Загрузчик тянет
  половину системы, и веха перестаёт быть первой. Отпадает.
- **C. Один `Finding` у `deduction`.** В нём нужны люди, должности, слой провала —
  вычислитель начинает знать предметную область. Отпадает.
- **D. Загрузчик только разбирает, все проверки — у линтера.** Смоук-тест
  шестнадцати дефектов уезжает на `corpus-checks`, и загрузчик больше не
  «заставляет схему существовать машинно». Отпадает.

**Рекомендация — A.**

## 8. Направление между `scenario` и `corpus`, `facts`

**Варианты.**

- **A. `scenario` требует `corpus` и `facts`.** Загрузчик порождает их начальные
  значения в их собственных типах. Типы нормы, документа и факта живут у владельцев
  состояния, которые переживают старт партии; нормы игрока в ходе партии создаются
  теми же типами, без сценария.
- **B. `corpus` и `facts` требуют `scenario`.** Они строятся из `*Scenario`, и
  сценарий становится пакетом моделей данных; корпусу всё равно нужен свой тип нормы
  для правок игрока, и типы задваиваются.
- **C. Ни то ни другое: сценарий отдаёт свои структуры, отображение — в точке
  сборки.** Двойные типы и код отображения ради разрыва зависимости, подстановки в
  которой не наблюдается.

**Рекомендация — A.** Граф: `scenario` требует `corpus`, `facts`, `deduction`;
циклов нет — `corpus` требует `period`, `facts` — `period` и `journal`. Следствие для
вех то же, что в вопросе 6: типы `corpus` и `facts` появляются на
`scenario-loader`, логика среза — на `derived-state`.

## Что станет с шестнадцатью дефектами

При всех рекомендациях. **Ошибка** — вычисление невозможно; **замечание** — корпус
загружен и плох.

| Дефект | Что выдаст загрузчик |
| --- | --- |
| `resolved-undefined`, `about-undefined`, `held-at-undefined` | ошибка: предикат не объявлен |
| `reviewable-rule-missing` | ошибка: ссылка на несуществующее правило |
| `reviewable-never-derived` | замечание: недоопределённое условие |
| `valid-unconsumed`, `unconsumed-rights` | замечание: мёртвый вывод |
| `duty-arity-mismatch`, `min-age-arity-mismatch` | ошибка: другая арность |
| `unbound-head-variable` | ошибка: небезопасное правило |
| `anonymous-variable-in-head-rules` | ошибка: недопустимый терм |
| `period-variable-unbound` | ошибка: небезопасное правило, пока `N` не заменён на `now` |
| `compound-terms-in-heads` | ошибка: недопустимый терм |
| `limit-undeclared` | ошибка: ссылка на необъявленную константу |
| `open-interval-arithmetic` | исчезает: интервал закрывается при чтении фактов |
| `duplicate-iteration-rule` | замечание: два правила с одинаковыми головой и телом — новая проверка |

Две правки, которые из этого следуют:

- **к списку ошибок загрузчика добавляются две**: недопустимый терм — составной,
  выражение в аргументе, анонимная переменная в голове — и рекурсия через счёт.
  Ссылка на необъявленную константу входит в существующую ошибку 4;
- **демонстрация вехи противоречит сама себе.** Сейчас записано «казусы
  загружаются, а дефекты выходят замечаниями», но большинство дефектов — ошибки, и
  казус с ними не загрузится. Честная формулировка: исходные казусы дают ожидаемый
  список ошибок и замечаний; исправленные загружаются и дают только замечания.
