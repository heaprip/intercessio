# Инструменты

## Подключено

**Lefthook** закреплён как versioned Go tool: `go.mod` содержит директиву
`tool github.com/evilmartians/lefthook/v2`. Pre-commit запускает проверки
структуры документов и staged impact; pre-push дополнительно запускает Go
tests и vet, если в репозитории есть отслеживаемые `.go` файлы. Условие
завязано на файлы, а не на `go.mod`: при пустом модуле `go test ./...`
возвращает ошибку.

Локальный хук — удобство, CI — обязательная граница.

**Проверки документации** — два скрипта, оба подключены в `lefthook.yml`:

- `scripts/check-docs.sh` — структура: обязательные файлы на месте, у решений
  допустимый статус, у заменённого решения есть строка `Superseded by`, черновики
  помечены, `guide/` не ссылается на `impl/`, висящих wikilinks нет;
- `scripts/check-doc-impact.sh` — staged changes: решение изменено без
  обновления индекса (жёстко), код изменён без единого документа (мягко).

Мягкий сигнал намеренно не блокирует коммит: путь файла не доказывает
смыслового влияния. В CI его можно ужесточить через `DOCS_IMPACT_STRICT=1`,
когда появится стабильная структура пакетов.

Скрипты проверяют механику и не переписывают смысл: семантическое
автообновление создаёт правдоподобную, но не подтверждённую историю.

## Кандидаты по мере роста

**Buf** — вместе с первой реальной `.proto`, не раньше. Версии remote plugins
закреплять явно, CI проверяет lint, breaking check, генерацию и отсутствие
diff. Сгенерированный OpenAPI проверяется отдельно: совместимость protobuf на
уровне wire не доказывает совместимость HTTP-путей и публичного SDK.

**Fitness-функции архитектуры** — когда появятся пакеты, добавить Go-тест или
анализатор, запрещающий импорты из домена в адаптеры и нежелательные
межконтекстные зависимости. Надёжнее ручной диаграммы, потому что проверяет
фактический граф.

**Symbol-aware toolkit (Serena и подобные)** — после первого вертикального
среза, когда символы появятся. Их память считается кэшем, а не источником
решений: второй канонический store создаст расхождение.

**LikeC4** — когда таблица компонентов перестанет помещаться в экран или
появятся минимум три стабильных отношения, которые действительно нужно
визуализировать. До этого DSL и Node-toolchain дороже диаграммы.

**AsyncAPI и EventCatalog** — только после появления внешнего потребителя и
версионируемого интеграционного события. Не описывать ими внутренние доменные
события: это снова свяжет ядро с контрактом транспорта.

**Vale** — prose linter, полезен при нескольких авторах и явном style guide.

## Что не автоматизировать

- принятие решения и перевод `Proposed` в `Accepted`;
- объяснение мотивации задним числом;
- удаление открытого вопроса потому, что код случайно реализовал один вариант;
- создание пакета или интерфейса из диаграммы.

Помощник может подготовить diff и перечислить затронутые документы. Смысл и
статус решения принимает автор.
