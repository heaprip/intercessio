# RouterAI: что узнано на спайке

Роутер, через который шёл спайк `spike/crack-finding`. Не выбор провайдера для
проекта. Справки по моделям —
[[docs/impl/llm-deepseek-v4.1-flash|DeepSeek V4.1 Flash]] и
[[docs/impl/llm-granite-4.2-8b|Granite 4.2 8B]]; здесь только то, что относится к
роутеру и к обеим моделям сразу.

Помечено: **страница** — сайт RouterAI, **замер** — вызовы спайка.

## Доступ и расход

- база `https://routerai.ru/api/v1`, совместим с OpenAI SDK, ключ в
  `Authorization: Bearer` (страница);
- расход приходит полем `usage.cost` **в рублях**, если в запросе есть
  `usage: {include: true}` (замер);
- исчерпанный баланс даёт **HTTP 402** (замер); вызов записывается как
  необслуженный.

## Провайдер закрепляется

- по умолчанию запрос уходит к дешёвому стабильному провайдеру, а при сбое **молча**
  к запасному (страница);
- закрепление — `provider: {order: [...], allow_fallbacks: false}` (замер на обеих
  моделях); кто обслужил, видно в поле `provider` ответа;
- **цена одной модели у разных провайдеров разная**: выход Granite — 16 ₽ за
  миллион у CoreWeave против 27 ₽ у DeepInfra (страница).

## Рассуждение

- **Поля рассуждения различаются по моделям даже через один роутер.** DeepSeek
  выключается только нативным `thinking: {type: "disabled"}`, поля `reasoning`
  роутера его не выключают; у Granite поля роутера работают (замер). Описание модели
  — данные, проверяемые пробными вызовами.
- Рассуждение возвращается полем `message.reasoning` (замер).
- **Режим рассуждения — главная статья расхода.** Участник DeepSeek с рассуждением
  дороже участника без него в 6–17 раз, полный режим Granite дороже низкого усилия
  примерно в 5 раз (замер).

## Кэш

Кэш провайдера работает на **совпадающем префиксе**: неизменная часть запроса —
системный текст, персона, нормы — идёт первой, переменная — в конце. В спайке из
кэша шло до 40% входных токенов (замер). Поле —
`usage.prompt_tokens_details.cached_tokens`.

## Структурированный выход

- Роутер принимает `response_format` со строгой схемой (замер на DeepSeek).
- **Наблюдение автора**: со схемой ответ через RouterAI сильно медленнее, а модель и
  без неё почти всегда отвечает JSON по просьбе в тексте. На тривиальных пробах
  разница не видна. Спайк просил JSON текстом и перезапрашивал.
- По литературе накладные расходы ограниченного декодирования на токен малы;
  задержку дают реализация провайдера и подготовка схемы. Сильнее другой риск:
  жёсткий формат может ухудшать рассуждение, особенно если поле ответа стоит в схеме
  раньше рассуждения — «Let Me Speak Freely?», EMNLP 2024, по поисковой выдаче. Это
  наблюдение о конкретном провайдере и моделях, а не общий вывод.
