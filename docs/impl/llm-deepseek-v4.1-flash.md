# DeepSeek V4.1 Flash через RouterAI

Модель, на которой идёт спайк `spike/crack-finding`. Это не выбор провайдера для
проекта — глава 6 прямо запрещает объявлять провайдера окончательным, — а
справка по конкретной модели и конкретному роутеру.

Цифры устаревают быстрее всего в каталоге. Каждое утверждение помечено, откуда
оно: **страница** — сайт RouterAI или DeepSeek, **каталог** — ответ `GET /models`
RouterAI, **карточка** — Hugging Face, **замер** — пробный вызов из этого
репозитория.

## Идентичность

| Что | Значение | Откуда |
| --- | --- | --- |
| Идентификатор в RouterAI | `deepseek/deepseek-v4.1-flash` | каталог |
| Псевдоним на текущую версию | `~deepseek/deepseek-v4-flash-latest` | страница |
| Модель у провайдера | `deepseek-flash` | замер: поле `model` ответа |
| Провайдер, ответивший на все пробы | `DeepSeek` | замер: поле `provider` ответа |
| Разработчик и веса | DeepSeek, `deepseek-ai/DeepSeek-V4.1-Flash` на Hugging Face | карточка |
| Лицензия | MIT | карточка |
| Выпуск | 10 сентября 2026 | страница DeepSeek |

У DeepSeek имена `deepseek-v4-flash` и `deepseek-v4-flash-vision-exp` временно
ведут на V4.1 Flash, а `deepseek-v4-pro` переводится на неё же с 14 сентября
2026. В каталоге RouterAI старые идентификаторы пока существуют отдельно и с
другими ценами.

## Устройство

По карточке Hugging Face:

- разреженная смесь экспертов, **552B параметров**;
- активных — **8B на чтении входа и 16B на генерации**;
- архитектура Causal Encoder–Decoder: 20 слоёв кодировщика и 20 слоёв
  декодировщика;
- в каждом слое 1 общий и 384 маршрутизируемых эксперта, на токен включается 6;
- обучение на 45T токенов мультимодального корпуса;
- вход — текст и изображения, выход — текст.

| Предел | Значение | Откуда |
| --- | --- | --- |
| Контекст | 1 048 576 токенов | каталог |
| Максимум вывода | 384K | страница цен DeepSeek |

## Цены в RouterAI

Рубли за миллион токенов. В каталоге цена указана за токен; миллион — пересчёт.

| Токены | ₽ за 1M | Откуда |
| --- | --- | --- |
| вход | 18,07 | каталог: `pricing.prompt` = 1,807e-05 |
| выход, включая рассуждение | 72,29 | каталог: `pricing.completion` = 7,229e-05 |
| чтение из кэша | 0,36 | каталог: `pricing.input_cache_read` = 3,615e-07 |
| запись в кэш | не указана | ни каталог, ни страница её не называют |

Страница называет ещё провайдеров Relace и Io Net с той же ценой входа и чтения
из кэша.

**Расход приходит в ответе** полем `usage.cost` в рублях, если в запросе есть
`usage: {include: true}`. Замер сходится с каталогом: 149 входных и 80 выходных
токенов дали 0,00848 ₽; 149 × 18,07e-6 + 80 × 72,29e-6 = 0,00847.

Режимы обработки RouterAI (`service_tier`: `flex` со скидкой около 50%,
`priority`) по странице доступны OpenAI, Google и xAI; DeepSeek в таблице нет.

## Кэш контекста

- **Включён всегда**, ничего настраивать не нужно; работает «по мере
  возможности», попадание не гарантируется (DeepSeek).
- **Совпадать должен префикс целиком.** Единицы кэша образуются на границах
  запросов, на общих префиксах разных запросов и через фиксированные интервалы
  в длинном тексте (DeepSeek).
- **Живёт** от нескольких часов до нескольких дней после последнего
  использования (DeepSeek).
- **Отчёт.** У DeepSeek напрямую — `usage.prompt_cache_hit_tokens` и
  `usage.prompt_cache_miss_tokens`. Через RouterAI — `usage.prompt_tokens_details.cached_tokens`
  (замер).

Замер через RouterAI:

| Запрос | Вход | Из кэша | Стоимость, ₽ |
| --- | --- | --- | --- |
| короткий, повтор | 149 | 0 | 0,0086 |
| длинный, первый | 4118 | 0 | 0,0820 |
| длинный, повтор через 3 секунды | 4118 | 3968 | 0,0129 |

Короткий запрос в кэш не попал: вероятно, он меньше единицы кэша. Следствие для
запросов: **неизменная часть — системный текст, персона, нормы — идёт первой**,
всё переменное — в конце.

## Режим рассуждения

По DeepSeek:

- включён по умолчанию, уровень по умолчанию — `high`;
- в формате OpenAI: `thinking: {type: "enabled" | "disabled"}` и
  `reasoning_effort: "low" | "high" | "max"`;
- в формате Anthropic: `reasoning: {effort: "none" | "low" | "high" | "max"}`,
  где `none` выключает рассуждение;
- в режиме рассуждения `temperature`, `presence_penalty` и `frequency_penalty`
  принимаются, но не действуют; `top_p` ниже 0,95 поднимается до 0,95;
- рассуждение возвращается полем `reasoning_content` рядом с `content`. Без
  `tools` его не нужно передавать обратно в следующих ходах; с `tools` —
  нужно.

По карточке уровень рассуждения у самой модели непрерывный, целое от 1 до 100;
API отдаёт три ступени.

**Через RouterAI — замер, и он расходится с ожиданием:**

| Что передано | Токенов рассуждения |
| --- | --- |
| ничего | 51 |
| `reasoning: {enabled: false}` | 46 |
| `reasoning: {effort: "none"}` | 55 |
| `reasoning: {effort: "high"}` | 45 |
| `reasoning_effort: "low"` | 42 |
| `reasoning_effort: "max"` | 47 |
| **`thinking: {type: "disabled"}`** | **0** |

Выключает рассуждение только нативное поле DeepSeek `thinking`. Поля
`reasoning` RouterAI для этой модели его не выключают. Разница между `low` и
`max` на тривиальной задаче не видна и требует задачи потяжелее.

RouterAI возвращает рассуждение полем `message.reasoning`, а не
`reasoning_content`.

## Структурированный выход

- **DeepSeek напрямую** поддерживает только `response_format: {type:
  "json_object"}`; в запросе должно быть слово «json» и пример формата; API
  «иногда возвращает пустой `content`».
- **RouterAI** в каталоге перечисляет `response_format` и `structured_outputs`.
  Замер: `response_format: {type: "json_schema", json_schema: {strict: true,
  schema: …}}` со списком допустимых значений принят, и все одиннадцать пробных
  ответов были валидным JSON со значением из списка — и с рассуждением, и без.
  Одиннадцать ответов на тривиальной задаче не доказывают, что ограничение
  строгое; проверка значения на своей стороне остаётся обязательной.
- **Цена схемы — задержка.** Наблюдение автора: структурированный выход через
  RouterAI очень сильно замедляет ответ, а модель и без него почти всегда
  отвечает в требуемой форме; дешевле разобрать ответ самому и при ошибке
  перезапросить. На пробах из этого репозитория разницы не видно, но пробы были
  тривиальными: около секунды на ответ в обоих режимах. Спайк поэтому просит JSON
  текстом и перезапрашивает.

## Маршрутизация

По странице RouterAI о выборе провайдера:

- **по умолчанию** запрос уходит к стабильному провайдеру с наименьшей ценой, а
  при сбое — к запасному, **молча**;
- закрепить провайдера — `provider: {order: ["DeepSeek"], allow_fallbacks:
  false}`; если он недоступен, придёт 404, а не ответ другого провайдера. Замер:
  запрос с таким полем обслужен DeepSeek;
- ещё есть `only`, `ignore` и `country`;
- кто обслужил, видно в поле `provider` ответа (замер; страница об этом
  молчит).

Для эксперимента закрепление обязательно: иначе разные вызовы одного участника
могут обслужить разные провайдеры.

## Прочее

- **Параметры в каталоге:** `frequency_penalty`, `include_reasoning`,
  `logit_bias`, `logprobs`, `max_tokens`, `min_p`, `presence_penalty`,
  `reasoning`, `reasoning_effort`, `repetition_penalty`, `response_format`,
  `seed`, `stop`, `structured_outputs`, `temperature`, `tool_choice`, `tools`,
  `top_k`, `top_logprobs`, `top_p`.
- **`seed`** по странице RouterAI даёт детерминизм «не для всех моделей»; для этой
  не проверено, а в режиме рассуждения выборка всё равно не управляется
  температурой.
- **Эндпоинты RouterAI:** `/chat/completions`, `/responses`, `/messages`; база
  `https://routerai.ru/api/v1`, ключ в заголовке `Authorization: Bearer`.
  Совместим с OpenAI SDK.
- **Рекомендации карточки:** `temperature` 1,0, `top_p` 0,95 или 1,0, лимит вывода
  от 256K — это настройки их замеров качества, а не требования API.
- **Развёртывание своих весов:** vLLM, SGLang, Docker Model Runner (карточка).
